# Red Atlas — API

Express REST API for Red Atlas, with pagination, sorting and text search over Postgres on [Neon](https://neon.com), queried with [Drizzle ORM](https://orm.drizzle.team). Deployed on Vercel at `https://red-atlas-api.vercel.app/api`.

See the [main README](../../README.md) for the endpoints, the reasoning behind the API and setup.

```bash
# from the repository root
pnpm dev:api   # http://localhost:3000/api/properties
pnpm migrate   # apply pending migrations
pnpm seed      # load the 10,000 sample properties
```

| Env variable | Description |
|---|---|
| `DATABASE_URL` | Postgres connection string. Use a separate Neon branch for local development |
| `APP_PORT` | Port for local development (default `3000`) |

```
├── config/            # Drizzle client over Neon's HTTP driver
├── controllers/       # HTTP only: parse the request, choose the status code
├── migrations/        # SQL generated by drizzle-kit, one folder per change
├── models/            # Drizzle table, queries, and row ↔ JSON mapping
├── routes/            # Express router
├── schemas/           # Zod schemas for the query params (the body's is in shared)
├── seeders/           # 10,000-property dataset + batched seeding script
├── drizzle.config.js  # drizzle-kit settings
└── server.js          # Entry point and error handler; exports the app for Vercel
```

## Changing the schema

The table is defined in `models/Property.js`, and its `CHECK` constraints are built from the values in `@red-atlas/shared`.

1. Edit the table (or the shared values).
2. `pnpm --filter api db:generate --name <change>` writes a new migration to `migrations/`.
3. Read the generated `migration.sql` before applying it.
4. `pnpm migrate` applies it to the database in `DATABASE_URL`.

Commit the migration folder with the code that needs it.
